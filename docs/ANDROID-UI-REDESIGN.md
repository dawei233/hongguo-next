# 安卓端 UI/UX 重设计规范（hongguo-next）

> **状态**：规范稿（未实施）。实施由移动工程师按 §9 分批落地。
> **基线**：`apps/android` @ 整端 vendor 自 `dawei233/guoapp-android`（`android-only` `ff3bad2`），
> M4b 只做了令牌镜像（`lib/ui/tokens.dart` + `app_theme.dart` 换色）+ 包名/图标/应用名。
> **令牌唯一来源**：`docs/DESIGN-SYSTEM.md` §3；Flutter 侧的具体字段名以
> `apps/android/lib/ui/tokens.dart` 为准（`HongguoTokens` 的 40 个 Color 字段 +
> `HnSpacing` / `HnTypo` / `HnMotion`）。
> 本文所有尺寸/颜色/动效都引用既有 token，**不新增色值**；§3 未定义的量（如进度条
> 4px 高度）直接给数值并注明来自哪个档位，不臆造 token 名。
> **本文范围**：安卓端的**结构重设计**。PC 端（`apps/desktop`，Electron + React）已有独立实现，不在本文范围。

## 0. 为什么必须重做（问题定性）

用户实测后的评价：

> 「这玩意和 guoapp 安卓版有区别吗。这不是没变化吗。我不是让 UI 设计师重新设计了吗，按现代类似播放器去设计。不要照抄上游项目啊。这 UI 和各种选项都一毛一样。」

这句话是**准确的**，而且指出了真正的交付缺口。M4b 做的是：

| 做了什么 | 性质 |
|---|---|
| `lib/ui/tokens.dart`（`HongguoTokens` 40 字段）+ `app_theme.dart` 改用令牌取色 | 换皮 |
| 包名 `duanju_app` → `hongguo_next`、应用名 → 红果 Next | 换标识 |
| 图标重做 | 换标识 |
| FFI 库名对齐 | 换管线 |

**没有动过**：信息架构、页面布局、导航结构、控制条组成、设置项组织、组件形状。
所以用户看到的是「同一个 App 换了配色」—— 这正是"只换皮"的定义。

本文要改的就是结构本身。

## 1. 设计方向声明

### 1.1 品类判断

这不是"视频网站"，也不是"视频工具"。短剧的物理事实是：

- **竖屏**（9:16 是原生画幅，不是横屏裁切）
- **单集 1–3 分钟**（不是 45 分钟）
- **强连续**（一集接一集，追剧是主行为，不是"挑一部看完"）
- **量大**（一部剧 50–100 集，榜单每天换）

所以核心行为是**刷**，不是**选**。上游把它做成了「视频工具 + 文件管理器」（下载/合并/推送/调试日记占满导航），这是**工具 App 的信息架构**，不是内容 App的。

### 1.2 与上游的五处结构性差异（不是配色差异）

| # | 上游做法 | 本次方向 | 为什么这是结构差异 |
|---|---|---|---|
| 1 | **底部 4 tab 平权**：发现 / 追剧 / 最近观看 / 下载 | **3 个目的地**：发现 · 我的 · 设置。追剧/最近观看/下载合入「我的」，三者为同级分段 | 上游把"同一件事的三个视图"（我保存的内容）拆成三个平级 tab，导致三处都要各自维护列表、空态、批量选择；合并后状态与操作可共享 |
| 2 | **发现页 = 筛选器 + 海报网格**（`CatalogFilters` 常驻一行分类 chip + 顶部搜索框） | **一屏一内容**：首屏即内容流（竖向大卡 + 横向主题轨），筛选收进右上 `⇅` 一个入口 | 上游把"选筛选条件"当成首屏主任务；实际主任务是"看有什么可刷"。筛选是低频动作，不该占首屏 |
| 3 | **播放器控制条 = 一长排工具**（实测标签：倍速 / 画质 / 弹幕 / 选集 / 亮度 / 音量 / 推送 / 原画对比 / 画中画 / 旋转与全屏 —— 10 项平铺） | **两级信息架构**：一级（常显）只留 播放 / 进度 / 上下集 / 全屏；二级（`⋯` 或手势唤出）收画质·倍速·弹幕设置·推送·画中画 | 上游把"设置项"当"控制项"。播放时的高频动作只有播放/暂停/快进/上下集；画质与倍速是**一次设定长期不变**，不该每次播放都出现在脸上 |
| 4 | **设置页 = 9 条平铺 `ListTile`**（外观主题 / 用户管理 / 设备互联 / 站源管理 / 播放调试日记 / 下载偏好 / 下载目录与空间 / 备份恢复 / 关于） | **4 个场景分组**：播放 · 内容与站源 · 数据与同步 · 关于；调试日记降级进入「关于 → 诊断」 | 9 条平权列表让用户逐个读才知道自己在哪；场景分组让"我要改播放行为"一步到位 |
| 5 | **平板横屏 = 手机布局拉伸**（`home_screen.dart:837` `desktop = maxWidth >= 840` 只是把底部导航换成 64px 图标 Rail；列数算法 `((width-36)/150).floor().clamp(1,8)` 直接吃宽度） | **平板横屏是一等形态**：主从结构（左导航 + 右内容）、内容区三栏、播放器选集侧栏常驻 | 平板横屏不是"宽一点的手机"。它有 1200×800 的可支配面积，能同时容纳导航+列表+详情/选集；当手机用等于浪费一半屏 |

**一句话方向**：从「**视频工具**」转向「**刷剧内容的书架**」—— 内容在前，操作在后；播放时极简，管理中分组。

## 2. 形态矩阵（三档，平板横屏为主力）

> **范围**（用户明确）：**TV / 10-foot UI 不在本次范围**；**平板只横屏用**，平板竖屏不设计。

| 形态 | 宽度 | 输入 | 布局骨架 | 主导航 | 内容列数 |
|---|---|---|---|---|---|
| **平板横屏** ★主力 | ≥ 900 且高 ≥ 600（横屏判定 `width > height`） | 触摸（双手持） | **主从**：左导航 88px 图标轨 + 右内容区 | 左侧图标轨（5 项：发现·追剧·最近·下载·设置）；不折叠 | 海报 `minmax(150px,1fr)` → 1200px 宽 **6 列**（**gap 必须计入**：7 张 ≥150px 卡 + 6×18px 间隙 = 1158px，而 1200px 扣除 88 左轨与 48 页边距只剩 1064px，强取 7 列会把卡片压到 136px、违反 150px 下界。实现按 auto-fill 公式 `floor((可用宽+gap)/(minW+gap))`：900→4、1200→6、1440→7、1600→8）；选集 **8 列**；横版主题轨 3.2 张可见 |
| **手机竖屏** | < 900 或（宽 < 高） | 触摸（单手持） | **单列栈**：无侧栏，底部导航 | 底部 3 项（发现·我的·设置） | 海报**固定 2 列**（`gap-x-3`）；选集 **4 列**；主题轨 2.4 张可见 |
| **手机横屏** | < 900 且（宽 > 高） | 触摸（双手持） | **主从（轻量）**：左导航 72px 图标轨 + 右内容区，但**发现页保持单列流**（横屏不为发现页扩列，因为竖屏内容是竖的） | 左侧 72px 图标轨（与平板同一套，只缩宽） | 海报**固定 3 列**（横屏宽度够但高度矮，避免一屏塞太多）；选集 **6 列** |

### 2.1 断点常量（写入 `lib/ui/layout.dart`，一处定义）

```dart
/// 形态判定只认「宽 + 朝向」，不认设备类型 —— 同一台平板旋转后是不同形态。
abstract final class HnBreak {
  static const double tablet   = 900;  // 横屏主从结构的最小宽度
  static const double railWide = 88;   // 平板左导航轨
  static const double railNarrow = 72; // 手机横屏左导航轨
  static const double railTabletMinHeight = 600;

  /// 列数算法（**取代** home_screen.dart:1511 与 detail_screen.dart:648 的两套）
  static int posterColumns(double width, {required bool landscape}) {
    if (width >= tablet && landscape) return ((width - railWide - 48) / 158).floor().clamp(4, 9);
    if (landscape)                   return 3;   // 手机横屏
    return 2;                                     // 手机竖屏
  }
  static int episodeColumns(double width, {required bool landscape}) {
    if (width >= tablet && landscape) return 8;
    if (landscape)                   return 6;
    return 4;
  }
}
```

> **为什么要统一**：现役有**至少四处**各不相同的列数算法（`home_screen` 的 `(width-36)/150`、`detail_screen` 的 `_episodeColumns`、`remote_widgets` 的 `values.minimum`、`recommendations_screen` 的 SliverGrid），同一个宽屏下发现页 7 列、选集 5 列、推荐 6 列，密度不一致（**注意：这里的"7 列"是旧算法（忽略 gap、卡片被压到 136px）的产物，不是应有效果；新算法在同宽度下应得 6 列**）。本规范收敛为**两个函数**。

### 2.2 竖屏 ↔ 横屏切换行为

| 场景 | 行为 |
|---|---|
| 应用内旋转（非播放） | `LayoutBuilder` 重新求值 → 形态切换 → **布局重排但保留滚动位置**（`PageStorageKey` 按 `形态+tab` 记忆，不用全局 key） |
| 进入播放全屏 | 沿用 `app_orientation.dart` 现有 `orientations()`：`aspectRatio >= 1` 锁横屏、否则锁竖屏。**这条逻辑不动** |
| 播放中横竖切换 | **控制层状态机不重建**。控制层是一个独立的 `Widget`，由 `_PlayerScreenState` 持有 `_controlsVisible` 等状态；横竖只换 `PlayerControls` 的 `layout` 参数（`compact | full`），**不换 widget 类型、不重置 `_controlsVisible`、不重置 `_seekSequence`** |
| 强制约束 | **禁止**为竖屏/横屏各写一套控制层实现。现役已有 `PlayerControls`（1091 行）+ `TelevisionControls`（697 行）**两份**，是重复的主要来源；本次要求**一份控制层 + layout 参数**（TV 那套随 TV 范围一起下线） |

> ⚠ **历史教训（必须遵守）**：hongguo-drama 的 PC 端曾因「全屏实现两套不一致」导致**控制条唤不出**（透明度过渡卡住 + `pointer-events` 离散属性不同步）。所以本规范硬性要求：**显隐状态机单点，形态只影响布局**。

## 3. 信息架构重排

### 3.1 旧 IA（上游）

```
底部 4 tab（平权）
├── 发现        分类 chip + 搜索 + 海报网格
├── 追剧        追剧列表（状态：在看/已完/待更 + 更新提示）
├── 最近观看    观看历史
└── 下载        下载任务（合集折叠）
                  └──（设置从哪进？上游从"最近观看"连点 6 次进站源密码锁）
```

问题：追剧 / 最近观看 / 下载 三者的**操作集几乎相同**（列表 → 打开/继续/删除/批量）；却各占一个 tab，各自实现空态、批量选择、长按菜单。设置入口藏在"连点 6 次"里。

### 3.2 新 IA

```
底部 3 项（手机竖屏）/ 左侧 5 项图标轨（平板横屏·手机横屏）
├── 发现          内容流：主题轨 + 海报墙，筛选收进右上 ⇅
├── 我的          三个分段（SegmentedButton）：追剧 | 最近 | 下载
│                   ├─ 追剧：在看 / 已完 / 待更
│                   ├─ 最近：按日期倒序
│                   └─ 下载：进行中 / 已完成
└── 设置          4 个场景分组（见 §6）
```

**平板横屏/手机横屏的左轨**（5 项，含分段的快捷入口）：

```
┌────┐
│ 发现 │  ← 选中态：primary-subtle 底 + primary 图标
│ 追剧 │  ← 直接进「我的 → 追剧」分段
│ 最近 │  ← 直接进「我的 → 最近」
│ 下载 │  ← 直接进「我的 → 下载」
│ 设置 │
└────┘
```

> **取舍说明**：横屏把三个分段**同时**放进左轨（而非只放「我的」），是因为横屏面积足够承载 5 项，且能少一次点击；竖屏保持 3 项是因为底部导航 4 项以上会挤压标签可读性（40px 宽 × 5 项 = 手机宽度 1/5，中文两字标签已到极限）。

### 3.3 搜索的位置

上游把搜索放在发现页内联展开。新 IA：**搜索是发现页的一个模式**（顶栏放大镜 → 顶栏变输入框，即"搜索态"），不单独占 tab。

### 4.2 播放器（重头戏）

#### 4.2.1 核心原则：两级信息架构

**一级（常显，3 秒无操作淡出）**

```
                 ┌──────────────────────────────────────┐
                 │  ← 剧名 · 第 5 集          [弹] [⋯]  │ ← 顶条 56
                 │                                      │
                 │                                      │
```

一级只有 **7 个可点区域**：返回 / 弹幕开关 / 更多 / 中央播放 / 进度条 / 上一集 / 下一集 / 倍速 / 全屏。

> 对比上游的 **10 项平铺**（倍速·画质·弹幕·选集·亮度·音量·推送·原画对比·画中画·旋转与全屏）——一级削减 **60%**。

**二级（`⋯` 或上滑唤出，`Sheet` 从底部/右侧滑入）**

```
┌ 播放设置 ──────────────────────┐
│ 画质        自动 1080P ▾       │
│ 倍速        1.0x ▾             │  ← 一次设定长期有效
│ 弹幕        开 ▾（透明度/字号/区域/速度 →）│
│ 选集        32 集 ›            │
│ 推送投放    局域网设备 ›        │
│ 画中画      关                 │
└────────────────────────────────┘
```

上游放在一级的「亮度 / 音量」**降级为手势**（见 §4.2.3），「原画对比 / 旋转与全屏」**删除**（前者是调试功能进「关于→诊断」；后者被形态自适应取代）。

#### 4.2.3 手势（竖屏横屏共用一套）

| 手势 | 动作 | HUD |
|---|---|---|
| 左半屏纵向滑 | 亮度（`AppDevice.setBrightness`） | 居中药丸 120×48：亮度图标 + 12 格条 + 百分比 |

**建议顺序**：B1 → B3 → B2 → B4 → B5 → B6 → B7。
**理由**：B1 是地基（零风险且后续都要用）；B3 是主力形态且不动导航（低耦合收益大）；B2 挪导航牵动测试，放在 B3 之后可以少改一次测试；B4 最复杂单独一批；B7 最后（等所有引用都迁走）。

### 6.2 防回归三原则

1. **控制层状态机单点**：B4 前后都只能有一份控制层实现。任何"为某形态新写一套控制"的改动一律拒绝。
2. **列数算法单点**：B1 后不得出现新的 `crossAxisCount` 字面量；CI 可加 grep 守卫（`grep -rn 'crossAxisCount:' lib/ | grep -v layout.dart` 应为空）。
3. **令牌不新增**：所有颜色/间距/圆角/字号/动效只能引用 `HnSpacing`/`HnTypo`/`HnMotion`/`HongguoTokens`。CI 已有的 `npx check:tokens` 需扩展覆盖 `apps/android/lib/ui/`（当前它只覆盖桌面端 CSS ↔ Dart 的一致性）。
